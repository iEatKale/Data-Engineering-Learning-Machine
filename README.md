# Data Engineering Learning Machine

This project investigates whether data engineering can be treated as a machine learning prediction problem. Instead of manually writing transformation scripts for each dataset, the system uses Large Language Models (LLMs) to infer transformation rules and generate cleaned CSV outputs from raw input data.

The project was developed as part of a BSc Computing Science dissertation at the University of Aberdeen.

## Project Overview

The pipeline takes a dirty CSV file as input and produces a cleaned CSV file as output.

It supports two main modes:

- **Reference mode**: the model is given dirty-clean example pairs to help infer the transformation rules.
- **No-reference mode**: the model receives only the dirty input data and must infer the required cleaning rules without examples.

The project compares the performance of three LLM providers:

- OpenAI
- Claude
- Mistral

The models are evaluated using exact match, row accuracy, column accuracy, and runtime.

## Environment Variables

The project uses API keys for the LLM providers. Create a `.env` file in the main project folder.

Example `.env` file:

```env
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini

MISTRAL_API_KEY=
MISTRAL_MODEL=mistral-tiny

ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=claude-haiku-4-5-20251001
```

Add your own API keys after each equals sign.

Do not upload or share the `.env` file publicly, as it contains private credentials.

## Running the Pipeline

The basic command format is:

```bash
python run.py <provider> <input_file> <mode>
```

The provider can be:

```text
openai
claude
mistral
all
```

The mode can be:

```text
ref
noref
```

If no mode is provided, the pipeline runs in reference mode by default.

## Running with References

Reference mode uses dirty-clean example pairs to help the model infer the transformation rules.

Example using OpenAI:

```bash
python run.py openai global_freelancers_raw_50.csv ref
```

Example using Claude:

```bash
python run.py claude messy_hr_100.csv ref
```

Example using Mistral:

```bash
python run.py mistral global_freelancers_raw_200.csv ref
```

To run all providers:

```bash
python run.py all global_freelancers_raw_50.csv ref
```

## Running Without References

No-reference mode only gives the model the dirty input dataset. The model must infer the required transformation rules without example outputs.

Example using OpenAI:

```bash
python run.py openai global_freelancers_raw_50.csv noref
```

Example using Claude:

```bash
python run.py claude messy_hr_100.csv noref
```

Example using all providers:

```bash
python run.py all messy_hr_50.csv noref
```

## Reference Pairs

Reference pairs are stored in:

```text
data/train_pairs/
```

The project contains reference pairs for both datasets:

```text
data/train_pairs/global_freelancers/pair_1
data/train_pairs/global_freelancers/pair_2

data/train_pairs/messy_hr/pair_1
data/train_pairs/messy_hr/pair_2
```

To use a specific reference pair, copy its dirty and clean CSV files into the active reference folder:

```text
data/train_pairs/pair_1/
```

The pipeline will then use that active pair during reference-based runs.

## Outputs

Each run creates two main output files:

```text
rules.json
cleaned.csv
```

The outputs are saved inside:

```text
data/outputs/<provider>/<mode>/<input_file_name>/
```

For example:

```text
data/outputs/openai/ref/global_freelancers_raw_50/
```

The `rules.json` file contains the transformation rules inferred by the model.

The `cleaned.csv` file contains the final cleaned output generated by the model.

## Evaluation

The generated outputs were compared against expected target outputs using the following metrics:

- **Exact Match**: checks whether the full generated output matches the expected output.
- **Row Accuracy**: measures how many rows match the expected output.
- **Column Accuracy**: measures how many columns match the expected output.
- **Runtime**: records how long each model takes to complete the transformation.

These metrics were used to compare model performance across different datasets, dataset sizes, and reference conditions.

## Notes

Some models may fail on larger datasets because of token limits or API restrictions. In this project, Mistral was less reliable on larger MessyHR inputs due to context limitations.

The generated CSV outputs should be checked carefully, as LLMs can produce formatting errors, incomplete outputs, or inconsistent transformations.
